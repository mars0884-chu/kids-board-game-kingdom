# 象棋入門完整遊戲規格（草案）

規格版次：`XIANGQI-SPEC-d02`
對應下一個產品版本：`v0.14.0`（原規劃 v0.8.0，排程已後移）
工作編號：`V140-SPEC`
狀態：規則來源已由製作人於 2026-09-25 核准；完整循環裁判尚待實作與測試
適用年齡：以 7 歲兒童為主要對象

> 正式裁判依據為中華民國象棋文化協會《中華民國象棋規則113年修訂版》；製作人已核准以此規則進行。來源：https://www.cccs.org.tw/Page?itemid=18&mid=35 。世界象棋聯合會規則只作疑難對照，不混用判決。兒童說明可簡化用語，不能改變勝負與和局結果。此規格確認不等於完整規則引擎或美術已完成。

## 1. 本階段目的與邊界

v0.14.0 的目標是以離線優先方式，讓兒童從棋子走法、將軍與保護自己的將／帥開始學習象棋。第一版應先證明「看示範、跟著做、提示練習、獨立完成」的學習循環，再逐步增加完整對戰策略。

預計包含：

- 可離線執行、可序列化與可重播的象棋規則核心。
- 互動教學、自由練習與同機雙人。
- 入門、成長、挑戰、成人版四階兒童友善自適應難度 NPC。
- 合法走法提示、將軍提醒、錯誤復原、暫停、返回、重玩與本機存檔。
- 結構化台灣繁體中文、每個中文字右側直排台灣注音與語音欄位。
- 固定亂數種子只用於教學局面、測試、NPC 回放與可重現問題。

不包含：

- 雙裝置連線、Firebase、WebRTC、後端、帳號或雲端存檔。
- 公開配對、聊天、兒童姓名、位置、分析追蹤、付費、廣告或隨機抽獎。
- 未經製作人確認的象棋規則變體、正式棋子素材、角色或場景。

| 將死 | 攻擊對方的帥／將，且對方無法躲避、阻擋或吃掉攻擊子，即將死獲勝 | 製作人已確認；引擎必須以合法走法判定，不由畫面猜測 |
| 困斃 | 輪到某方且所有棋子都沒有合法走法，該方被困斃而輸棋 | 製作人已確認；與被將軍但無法解圍的將死分開記錄 |
| 和局 | 雙方皆無力將死對方，或雙方合議和局 | 「無力將死」需要可測試的棋子材料判定；合議和局由明確操作觸發 |

| 自然限著 | 協會規則記載雙方連續共 100 著未吃子時可判和 | 兒童版不以倒數施壓；自動判定前須驗證吃子重設與將軍例外 |
| 將／帥接觸 | 兩者不可在同一直線無隔子相對 | 製作人已確認此標準限制，會納入合法走法與將軍測試 |

製作人已確認採用上述協會規則；表中其餘歷史「建議」用語只供工程細化，不得與正式規則衝突。

### 2.1 循環盤面裁判的工程契約

1. 以協會規則第「循環盤面之判決」為唯一正式勝負來源。比較雙方長將、長捉與未犯例；雙方同等犯例或均未犯例而不變著時作和，犯例較重的一方不變著時判負。
2. 長將高於長捉；一方長將而對方長捉或未犯例，長將方不變著判負。單方長捉而對方未犯例，長捉方不變著判負。
3. 長捉分類需涵蓋同一子或多子持續捉同一子、真根與假根、同類子、兵卒與將帥、牽制、兼兌及「一將一捉」等協會列出的例外，不可以「每步都攻擊對方棋子」直接判長捉。
4. 保留每步完整局面、走棋方、將軍狀態與攻擊／受保護棋子資料，以便重播及證明裁判結論。無法可靠分類的局面不可擅自判負；正式上線前須補齊測試或明確標示未完成。

## 3. 建議採用的標準棋盤與棋子

### 3.1 棋盤與座標

1. 棋盤為 9 欄、10 列，以棋線交點作為棋子位置，共 90 個交點。
2. 中央有一條楚河漢界；棋子可以在河岸與己方半場內依規則移動。
3. 紅方與黑方各有 16 枚棋子：將／帥 1 枚、士／仕 2 枚、象／相 2 枚、車 2 枚、馬 2 枚、炮 2 枚、兵／卒 5 枚。
4. 紅方、黑方以顏色之外的文字、形狀與位置辨識；不得只以紅綠色差異表示陣營。
5. 技術座標採 `row`／`column` 與可序列化索引；兒童畫面不直接顯示技術索引。
6. 棋盤保持正方形交點比例，不因直向或橫向畫面拉伸；手機直向採棋盤與資訊區上下排列，平板橫向採左右排列。

### 3.2 初始排列

1. 初始局面必須由固定資料建立，並以規則核心驗證所有棋子數量、顏色與位置。
2. 標準初始局面紅方位於棋盤下方、黑方位於棋盤上方；紅方先手。
3. 教學可使用固定種子與少量棋子局面，但不得把教學局面誤當成正式對戰初始排列。
4. 自由練習與同機雙人使用標準初始排列，不使用會改變棋規的隨機洗牌。

## 4. 建議的基本走法

下列文字是給規則引擎與測試使用的精確草案；兒童介面之後另以示範、圖示、語音與短句說明。

| 棋子 | 走法草案 | 重要限制 |
| --- | --- | --- |
| 將／帥 | 在九宮內上下左右走一格 | 不得走入被攻擊的位置；雙方將／帥不可隔著沒有棋子的直線相對 |
| 士／仕 | 在九宮內沿斜線走一格 | 不可離開九宮 |
| 象／相 | 沿斜線走兩格 | 象眼不可被堵；不可過河 |
| 馬 | 先沿直線走一格，再向斜角走一格 | 馬腳被堵時不能走 |
| 車 | 沿橫線或直線走任意格 | 不可越過其他棋子 |
| 炮 | 不吃子時沿橫線或直線走任意格；吃子時必須隔一枚棋子 | 炮架只能有一枚，不能隔兩枚或零枚吃子 |
| 兵／卒 | 過河前向前走一格；過河後可向前、左、右走一格 | 不可後退；不得以斜角移動 |

吃子時，目的格必須有對方棋子，且移動規則與將／帥安全檢查都必須通過。己方棋子不得互吃；不得以畫面直接判斷合法性。

## 5. 將軍、將死與和局

### 5.1 將軍與安全局面

1. 一方的將／帥受到對方合法走法攻擊時，局面標記為「被將軍」。
2. 被將軍的一方只能走出能解除攻擊的合法棋步：移動將／帥、吃掉攻擊棋子、或用棋子阻擋可阻擋的攻擊路線。
3. 任何一步若讓己方將／帥仍被攻擊，或造成兩將／帥無隔子相對，均為非法走法。
4. 將軍提示要以棋盤高亮、圖示與語音一起呈現，不只依賴長篇文字。

### 5.2 終局與和局草案

- 將死：輪到一方走棋且被將軍，同時沒有任何合法解法，該方判負。
- 無子可走：輪到一方且沒有任何合法走法時，依製作人確認判為困斃，該方輸棋；若同時被將軍，則記為將死，不重複記為困斃。
- 無力將死：若雙方都沒有足以形成將死的棋子材料，判和；實作前需把「足以將死」的材料集合寫成可測試規則。
- 合議和局：雙方明確操作同意後判和，不以單方按鍵直接結束對局。
- 反覆局面：依本規格第 2.1 節與協會 113 年修訂版比較雙方行為；現有引擎只追蹤局面，不宣稱已完成長將／長捉裁判。

## 6. 教學與遊戲模式草案

### 6.1 六段互動教學

| 段落 | 學習目標 | 示範局面 |
| --- | --- | --- |
| 1 | 認識棋盤、紅黑雙方與輪流走棋 | 少量車與兵，完成一格直走 |
| 2 | 認識車與炮 | 觀察車直走、炮架吃子，不能隔兩枚棋子 |
| 3 | 認識馬與象 | 用標記示範馬腳、象眼與象不能過河 |
| 4 | 認識士與將／帥的九宮 | 在九宮內移動並避開被攻擊格 |
| 5 | 認識兵／卒過河後的走法 | 比較過河前後可走方向，明確不能後退 |
| 6 | 學習將軍與解除將軍 | 先看示範，再在兩至三個候選走法中選安全解法 |

每段都採「看示範、聽規則、兒童操作、完成回饋、可重玩」；答錯時保留局面，先指出棋子走法或危險區域，再提供下一層提示，不直接替兒童完成整題。

### 6.2 自由練習與同機雙人

1. 自由練習提供四階 NPC；難度調整搜尋深度、候選範圍、評估雜訊與提示頻率，不改變合法棋規。
2. NPC 不讀取玩家看不到的資訊，不故意走非法棋步，也不連續做出荒謬錯誤。
3. 同機雙人雙方手動操作，不顯示 NPC 難度；換手時只提示目前玩家，不反覆旋轉整個畫面。
4. 教學、自由練習與同機雙人均可暫停、返回、重玩與從 IndexedDB 恢復；不因切到背景直接判負。

## 7. 資料、文案與測試契約

### 7.1 可序列化局面

規則核心至少需要保存：

```ts
interface XiangqiPosition {
  version: 1
  board: Array<XiangqiPiece | null>
  currentPlayer: 'red' | 'black'
  moveHistory: XiangqiMove[]
  repetitionCounts: Record<string, number>
  status: 'playing' | 'check' | 'checkmate' | 'draw'
}
```

載入資料時必須重新驗證棋子數量、棋子種類、位置、回合、走棋紀錄與終局狀態；不得信任畫面或存檔直接宣告勝負。

### 7.2 兒童內容

正式實作至少需要遊戲名稱、棋子名稱、輪到誰、合法走法提示、將軍、解除將軍、吃子、將死、和局、返回、重玩、暫停、聽一聽與正向終局回饋等文案。每筆 `audience: child` 資源都必須有：

- 台灣繁體中文。
- 每個中文字與自己的右側直排台灣注音配對。
- `speech_zh_tw` 與語音鍵值。
- 與實際棋規相符的語境注音；不得由畫面臨時拼接完整句子。

### 7.3 規則與互動測試

正式引擎前至少建立：

1. 32 枚棋子與標準初始排列驗證。
2. 每種棋子的合法走法、吃子與邊界測試。
3. 馬腳、象眼、炮架、九宮、河界、兵／卒過河與不可後退測試。
4. 將軍、飛將、解除將軍、將死與無子可走測試。
5. 無力將死、合議和局、反覆局面追蹤、可配置步數規則、序列化、回放與非法存檔拒絕測試。
6. 四階 NPC 只回傳合法走法、固定種子可重現且不讀取隱藏資訊測試。
7. 教學每段可完成、可重玩、答錯可復原，以及兒童介面按鍵與頁面無溢位測試。
