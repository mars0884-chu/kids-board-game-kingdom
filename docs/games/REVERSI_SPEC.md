## 1. 目的、範圍與非範圍

黑白棋（Reversi／Othello）是五子棋完成後的下一個完整棋類縱切。本規格採用製作人指定的標準 8×8 規則，並預定重用既有 PWA 的共用回合介面、逐字右側台灣注音、裝置語音、離線存檔、四階 NPC、互動教學、自由練習與同機雙人框架。

本文件確認規則、資料契約、可測試案例及兒童模式範圍；它不授權建立規則引擎、React 畫面、兒童文案資源、黑白棋棋盤／棋子／場景或正式封包。黑白棋正式兒童美術必須另建唯一 ART 編號，完成正式程式四方向一比一組合畫面並取得製作人確認後才可進入產品。

## 2. 正式採用規則

### 2.1 棋盤、座標與開局

- 棋盤為 8×8 正方形，共 64 格；棋子落在格子中央，不使用五子棋交點。
- 規則核心以 0 起算的一維索引序列化：`move = row * 8 + column`；`row`、`column` 均為 0 至 7。面向玩家的座標以欄 A 至 H、列 1 至 8 表示，A1 對應索引 0。
- 黑方固定先手，白方後手。
- 開局中央四格採交叉排列：D4、E5 為白棋；E4、D5 為黑棋。對應索引分別為 27、36、28、35。
- 新局的黑方合法格必須剛好是 D3、C4、F5、E6（索引 19、26、37、44）；此為規則、教學與畫面驗收的共同基準。

### 2.2 合法落子與翻轉

- 只能在空格落子。
- 由新落下的棋子向八個方向依固定順序檢查：上、右上、右、右下、下、左下、左、左上。
- 某方向必須先緊鄰一顆或多顆對手棋，且這串對手棋的另一端由本方既有棋子封住，才形成可翻轉線；中間不得穿過空格、棋盤外或本方棋子。
- 一步必須至少形成一條可翻轉線；沒有任何翻轉棋子的空格不是合法落子。
- 合法落子必須同時翻轉所有方向上被包夾的對手棋；玩家、NPC 與畫面都不得選擇只翻部分方向。
- `getFlips(state, move)` 回傳該步依固定方向順序收集的全部被翻棋子；若步不合法則回傳空陣列。`getLegalMoves(state)` 只回傳 `getFlips` 非空的空格，並依索引遞增排序。

### 2.3 強制略過、終局與勝負

- 輪到某方卻沒有合法落子時，系統必須自動略過該方回合；兒童不需要、也不能按「略過」來改變規則。
- 自動略過後，若另一方有合法落子，立即改由另一方下；若另一方也沒有合法落子，棋局結束。
- 棋盤 64 格填滿時，落下最後一子後立即結束，不額外產生略過紀錄。
- 終局時計算黑、白棋數量；棋子較多者獲勝，數量相同為和局。
- 不採用認輸、限時、重複局面和局、隨機改棋盤或任何非標準勝負規則。

## 3. 規則核心與可重播資料契約

### 3.1 型別與局面

規則核心獨立於 React，使用下列概念；實際 TypeScript 命名可在 V070-ENGINE 依此契約建立。

| 資料 | 必要內容 |
| --- | --- |
| `ReversiPlayer` | `black` 或 `white` |
| `ReversiCell` | `black`、`white` 或 `null` |
| `ReversiMove` | 0 至 63 的整數索引 |
| `ReversiMoveRecord` | `{ kind: 'move', player, move }`；翻子由規則重播計算，不信任存檔中的副本 |
| `ReversiPassRecord` | `{ kind: 'pass', player }`；只可由規則核心在該方確實沒有合法步時自動建立 |
| `ReversiTurnRecord` | `ReversiMoveRecord | ReversiPassRecord`，保存完整回合順序 |
| `ReversiState` | `version: 1`、`boardSize: 8`、`startingPlayer: 'black'`、64 格 `board`、`currentPlayer`、`phase`、`winner`、`blackCount`、`whiteCount`、`consecutivePasses` 與 `turns` |

`phase` 固定使用既有共用介面的 `playing`、`won`、`draw`。`winner` 僅在 `won` 時為 `black` 或 `white`；和局與進行中均為 `null`。`blackCount` 與 `whiteCount` 是棋盤重新計算的結果，載入時不可直接信任。

### 3.2 轉移規則

規則核心至少提供 `createReversiState`、`getFlips`、`getLegalReversiMoves`、`mustPass`、`applyReversiMove`、`resolveForcedPasses`、`getGameResult`、`replayReversiTurns`、`serializeReversiState` 與 `deserializeReversiState`。

1. `applyReversiMove` 拒絕範圍外索引、非空格、沒有翻子的空格與終局後操作。
2. 有效落子後一次翻轉 `getFlips` 的全部棋子、寫入一筆 `move` 紀錄，並暫時切換至對方。
3. `resolveForcedPasses` 在每一步之後、建立局面後與重播每筆紀錄時執行；只要目前方無合法步且棋盤未滿，就追加一筆 `pass` 紀錄並切換玩家。
4. 若連續兩次合法的自動略過發生，或盤面已滿，`getGameResult` 立即產生終局；終局局面不再保留可走步或可略過的玩家。
5. 對外穩定的 `playing` 局面不得讓 UI 面對「沒有合法步卻尚未略過」的狀態；`mustPass` 仍保留給規則測試、內部解析與無法穩定的候選局面檢查。

### 3.3 序列化、重播與版本遷移

- 儲存資料必須以 `turns` 為唯一事實來源。重播從標準開局重新執行每一筆 `move`，由規則核心自行推導所有必然的 `pass`，再把生成的完整回合紀錄與儲存的 `turns` 逐筆比對；不得把已自動產生的略過再當成外部指令重複套用。
- 每筆移動紀錄的玩家、落點、當時所有翻子、略過時機、目前玩家、棋盤、棋子數量、終局結果與連續略過數，都必須與重播結果一致；任一不一致、手動插入略過、跳過必須略過的回合、終局後加步或無效 JSON 都要拒絕載入。
- `version: 1` 是本規格的第一個儲存格式。後續資料結構變更只能新增明確遷移函式；舊版不能以猜測欄位或靜默重置進度處理。
- NPC 難度、固定整數種子、模式、提示層級、教學步驟、冒險關卡與已完成星章屬 session 資料；其中棋局仍必須由上述 `serializedState` 重播驗證。

## 4. 必要自動測試與固定局面

V070-ENGINE 必須將以下案例建立為規則或整合測試；任一項失敗即不能視為規則核心完成。

| 類別 | 必須驗證的結果 |
| --- | --- |
| 開局 | 8×8、中央四子、黑方先手、合法格剛好為 19、26、37、44 |
| 八方向 | 每一方向各有一個局面可翻至少一子；邊界外、空隙與未被己棋封住的對手串均不可翻 |
| 單向／多向 | 單方向翻子正確；一手同時翻兩條以上方向時，所有方向的棋子都翻轉且不得漏翻或重複翻 |
| 非法操作 | 拒絕範圍外、已占用、沒有夾住對手棋的空格、手動略過、終局後加步 |
| 強制略過 | 人工合法局面中，目前方無合法步、對方有合法步時，自動追加一筆正確玩家的 `pass` 並換手；使用者不需操作 |
| 連續略過 | 雙方皆無合法步但未滿盤時，依序記錄兩筆 `pass` 後終局；不得誤判為和局或繼續下棋 |
| 滿盤 | 最後一手填滿 64 格時立即終局、沒有額外 `pass`；分別驗證黑勝、白勝與 32 比 32 和局 |
| 計數與結果 | 每次有效落子後黑白數量與棋盤一致；棋子較多者勝，數量相同為和局 |
| 重播與竄改 | 含自動略過的局面可序列化與還原；拒絕竄改棋盤、計數、目前方、結果、略過紀錄、走棋玩家、終局後加步及無效 JSON |
| 不變性 | 所有查詢函式不得修改傳入局面；相同局面與紀錄的重播結果完全相同 |

固定局面可用座標圖或已驗證的 `turns` 建立；任何教學／冒險局面都必須由合法重播產生，不能直接塞入不可達的棋盤陣列。

## 5. 兒童學習設計與遊戲模式

### 5.1 學習目標與引導原則

目標是讓 7 歲兒童先看出「兩端包住就會翻面」，再逐步理解多方向翻轉、選擇空格、角落與沒有可走格時的自動略過。介面必須同時用形狀／圖示、外框與色彩標示合法格，不能只依黑白或紅綠色相。所有錯誤操作維持棋盤不變，以棋棋貓提供正向說明與下一層提示；不得扣分、倒數、羞辱或替兒童直接完成關卡。

### 5.2 互動教學

教學固定採「看示範 → 跟著做 → 提示練習 → 獨立完成」，每一步只引入一個概念：

1. **認識開局**：顯示標準中央四子，辨識黑方先手與四個合法格；四格皆可接受，避免把正確答案偽裝成唯一答案。
2. **包住一條線**：在可合法重播的小局面中，下出只翻一條線的一步，觀察被包住的白棋翻成黑棋。
3. **一次翻好多方向**：在可合法重播的小局面中，選一個同時翻至少兩方向的合法格，清楚逐方向呈現翻面結果。
4. **先想對方**：在固定局面中找出能避免下一手讓出角落或大量可走格的候選；若有多個合理保護格，全部接受。
5. **沒有格子時**：使用可合法重播的局面示範一方沒有合法格，棋棋貓說明系統會自動換手，兒童不會被標示為失敗。
6. **獨立短局**：以縮短、仍遵守完整規則的局面完成一盤，結算棋子數並給予可略過的正向回饋。

每一步的固定局面、可接受落點集合、預期翻子集合、目標提示層級與完成條件，都必須是資料驅動且有自動測試。教學重玩不降低已解鎖的 NPC 難度。

### 5.3 冒險闖關、自由練習與同機雙人

| 模式 | 範圍與完成原則 |
| --- | --- |
| 冒險闖關 | 使用經重播驗證的固定短局面，依序練習單向翻轉、多向翻轉、保護角落與自動略過。每關至少接受所有達成同一學習目標的合理合法步，不用唯一像素位置判定。提示為重述目標、指出區域、顯示候選、示範一步四層；完成後保留本機智慧星章。 |
| 自由練習 | 完整 8×8 對局，可選入門、成長、挑戰、成人版 NPC。難度只改變 NPC 決策，不能改變合法步、翻子、略過或勝負。 |
| 同機雙人 | 黑方與白方在同一裝置輪流操作。換手時顯示目前玩家；自動略過以清楚可重播的提示告知，不能要求玩家自行按略過。平板橫向是主要體驗，但四方向均可操作。 |
| 存檔／恢復 | 各模式獨立保存，恢復後必須回到相同局面、回合、已自動略過紀錄、提示階段與關卡進度。讀取失敗時保留原資料並安全開始新局，不得把竄改內容當成有效進度。 |

### 5.4 四階 NPC 的可測試邊界

所有 NPC 只讀取規則核心公開局面，只選 `getLegalReversiMoves` 回傳的落點，並使用固定整數種子提供可重現決策。入門、成長、挑戰、成人版都不得故意下非法步、讀取不存在的隱藏資訊、改變棋盤或連續做荒謬讓棋。

| 難度 | 決策範圍 | 最低測試要求 |
| --- | --- | --- |
| 入門 | 在合法步中偏好可理解的翻子與鄰近發展，於分數接近時以種子選擇合理不同走法。 | 合法率 100%、固定種子可重播、候選不足時不回傳空值。 |
| 成長 | 優先取得立即角落，開始避開尚未受保護角落旁的危險格，並比較下一回合行動力。 | 固定局面會選可得角、避免明確送角；合法率 100%。 |
| 挑戰 | 比較自己的落子後對手可走格數、角落風險與穩定邊線，採至少一層對手回應預判。 | 固定攻防局面不漏掉對手立即角落或明顯高行動力回應；固定種子重播。 |
| 成人版 | 使用受限深度搜尋，依序評估角落、穩定棋、行動力、邊線、終局棋差與對手反制；空格很少時可延伸至完整終局搜尋。 | 固定局面在目標裝置測試中於 600 ms 內回應、合法率 100%、相同種子結果相同，並在多種同分局面保有可重現的多樣性。 |

NPC 測試另須覆蓋：有合法步時不回傳 `null`、沒有合法步時只由規則核心建立略過、同一局面／難度／種子回傳相同結果，以及每個難度不會越過終局操作。

## 6. 內容、注音、語音與回饋契約

- 只有實作進入兒童畫面的文字才新增到結構化內容資料；每筆 `audience: 'child'` 都必須包含 `text_zh_tw`、逐字 `segments`、`speech_zh_tw`、唯一 `audio_asset` 與台灣繁體中文。
- 必備文案範圍：遊戲名稱、輪到你／對方、合法格、翻面結果、四層提示、自動略過、換手、棋子計數、黑勝／白勝／和局、錯誤操作、暫停、重播、返回與再玩一次。
- 每個中文字與自己的台灣注音必須形成不可拆單位，注音固定直排於字右側；窄版只可整組換行。既有 `BopomofoText`、內容檢查與版型檢查皆維持發布阻擋。
- 語音可重播、暫停與略過，且快速操作時不得重疊播放；語音高亮目前詞語但不能阻斷操作。
- 自動略過的兒童訊息固定表達規則與鼓勵，例如「這一回合沒有可以翻轉的格子，換對方試試看」，不使用「你不能下」或失敗標籤。

## 7. 響應式與正式美術 Gate

- 手機直向採棋盤在上、資訊／操作在下；手機橫向、平板直向、平板橫向與電腦共用平板橫向版型採棋盤與資訊／操作左右排列。
- 棋盤永遠維持正方形，8×8 格子不得拉伸；棋格與主要操作目標至少 48×48 CSS px。若可用空間不足，先重排操作區，不縮小必要操作文字或拆開逐字注音。
- V070-ENGINE 可使用無正式美術的技術佔位版面做內部規則、觸控與排版驗證，但不可稱為正式美術、不可送正式驗收、不可進正式封包。
- 正式美術必須在規格與引擎完成後另建唯一提案編號，沿用已核准 ART-001／ART-002／ART-004 的適用方向，並提供 390×844、844×390、768×1024、945×768 四張未裁切、未縮放、未後製且沒有截圖專用 CSS 的 1:1 正式程式畫面。未經製作人確認不得載入正式 PWA 或封裝。
